# AI Kit MVP intent

AI Kit makes a new, existing, or damaged software repository legible, reproducible, and continuously verifiable to a fresh coding agent. Months of work must not depend on chat history or optimistic test results.

## Required outcomes

1. Preserve user work. Never silently overwrite human edits, discard source changes, rewrite accepted requirements or decisions, or weaken failing tests to manufacture success.
2. A fresh agent can quickly find project purpose, approved requirements, accepted decisions, current status, acceptance contracts, and verification commands. Assumptions and temporary notes must not become authority.
3. Repositories can initialize and refresh their agent support reproducibly. Repeated operations are safe; manual edits are detected, preserved, and accompanied by a resolution path.
4. Acceptance criteria are agreed before implementation. Completion requires every required check to pass for the current product and contract; missing, failing, unknown, or stale evidence cannot establish success.
5. Developers receive fast feedback during iteration and comprehensive evidence before completion. Local and remote verification apply the same project requirements and expose failures honestly.
6. Existing repositories can be inventoried and baselined without modifying their source or hiding inherited failures. Reports distinguish claims, observations, inferences, and unknowns.
7. Web acceptance covers real user behavior and relevant frontend, backend, and runtime failures. Passing tests alone does not establish the user outcome.

Architecture and implementation scope are recorded in [accepted decisions](../decisions/README.md).
